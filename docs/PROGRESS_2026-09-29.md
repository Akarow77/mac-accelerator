The 41 ms synthetic inference measurement and 107 ms raw snapshot transfer
measurement are **different workloads**. They must not be combined into a claim
that a live camera/model path meets 20 Hz. The initial cap-only ABBA comparison
showed no clear gain (~127.47 ms chunks vs ~130.14 ms single), so increasing
message size alone is not established as the improvement.

## Fixed or handled in experimental tooling

- Legacy device ADB command-length/PTY limitations: compact in-memory bootstrap
  for stdlib probes and private temporary staging for the actual client. Program
  compression is separate from measured data; no payload compression credit.
- Authenticated transport test server's timeout budget incorrectly carried
  between paced requests. Each request now starts a fresh bounded budget.
  This was a **test-harness bug**, not a diagnosed production protocol failure.
- Actual padded camera buffers exceeded the 4 MiB frame cap: initially rejected,
  then tested with bounded chunks and an explicit bench-only 8 MiB override.
  Checksums, HMAC, sequence checks and size bounds remain.
- CPU-affinity preflight refuses unavailable cores. Explicit CPU-online holds
  are bounded to at most 120 seconds and abort at 75°C; normal cleanup restores
  original state when still offroad, and yields rather than offlining onroad.
  This is not a persistent performance-core setting.
- Camera snapshots exclude the cabin camera and image files; only independently
  started camerad is stopped. Existing camerad is refused, not hijacked.
- Controlled recovery: preserved experimental branch, restored clean sunnypilot
  master; retained private reset evidence before disconnect. This is recovery
  work, **not a fix for the unresolved electrical reset**.

Earlier work already documented in [historical project status](PROJECT_STATUS.md)
includes extracting the Mac app into this independent repository, removing the
old synchronous local-model capture hook from the device research branch, and
repairing a prior parameter-ownership boot error. Those are not newly discovered
fixes in this update. Model artifacts are not redistributed.

## Not adopted / not solved

- Larger socket buffers, forced socket limits and small raw-TCP send chunks did
  not show a reliable improvement worth production deployment.
- No new GPU/ANE parallel split or zero-copy inference pipeline was deployed.
- High-core affinity can compete with modeld/camerad; no coexistence claim.
- Calibrated continuous camera E2E, long-run tails, thermal soak, stale-result
  handling and disconnect behavior alongside local modeld remain unqualified.
- Direct Mac USB power instability remains unresolved, even on restored master.
- M1 and other Apple Silicon variants have not been validated by these M2 results.

New source-backed candidate: Chestnut copies only the NV12 image extent, not the
entire camera allocation. At the inspected 3X layout, 4,804,608 → 3,735,552 bytes
would remove ~22.25% of snapshot payload. This is **not an implemented speedup**;
see [the source trace and 1 GbE budget](USB_POWER_ISOLATION_RESEARCH_2026-09-29.md#follow-up-does-chestnut-send-raw-frames).

## Verification and public scope

Local software regression suite: **98 tests passed**, including four new checks
for default/experimental size limits and identical authenticated iovec payloads.
Static checks pass for the new bench tools/tests. These checks do not validate
vehicle safety, source selection or an electrical fix.

New tools are experimental and opt-in; they are not automatically started by the
Mac app. Device benchmark tools must stay off vehicle-connected devices while
the power issue is open. Documentation and source may be published; raw device
logs, addresses/identifiers, auth keys, models and camera images remain private
or excluded. Physical measurements are reported as aggregates with limitations.
