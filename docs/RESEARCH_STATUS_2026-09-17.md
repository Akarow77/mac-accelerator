# Research status — 2026-09-17

## 현재 결론

MacBook Air M2에서 모델 연산과 GPU/ANE 파이프라인의 가능성을 실측했습니다.
하지만 **실차 제어용 가속기는 완성되지 않았으며, 현재 공개 코드는 맥 단독
벤치마크·관찰 전용입니다.** 최신 실험에서는 3X에 접근하거나 소프트웨어를
변경하지 않았습니다. 앱 기본 추론 경로는 비분할 Core ML CPU+ANE로 유지합니다.

## 결과를 읽는 방법

| 범위 | 확인한 결과 | 의미와 한계 |
| --- | --- | --- |
| GPU(N+1)/ANE(N), 포화 입력 | 동일 분할 모델의 직렬 29.86fps → 파이프라인 50.61fps | 호출 겹침 확인. 개별 프레임 평균 지연은 40.06ms. 하드웨어 점유율 측정은 아님 |
| 20Hz 입력, 40-op 분할 | 비분할 평균 28.48ms vs 분할 45.48ms | 예약 시각부터 결과까지. 분할은 120회 중 52회 50ms 초과하므로 기본값으로 채택하지 않음 |
| 더 작은 9/17-op 분할 | 각각의 비분할 기준보다 지연이 나쁨 | 모든 분할점을 탐색한 것은 아님. M2 한계라는 결론은 아님 |
| 모델 없는 TCP localhost | IPv4 평균 0.738ms, IPv6 0.784ms | 인증·프레이밍·결과 검증 포함. 실제 USB/NCM 성능은 측정하지 않음 |
| 최신 비분할 localhost 관찰 | 200프레임 완료, 완전 이력 69프레임 구간에서 50ms 초과 0회 | 짧은 합성 입력 검사. 실차/장시간 검증이 아님 |
| 과거 실제 3X 카메라 실험 | 카메라 EOF부터 결과까지 평균 약 73.54ms | 다른 조건의 과거 실험. 맥 단독 추론 시간과 단순 차감해 네트워크 시간으로 볼 수 없음 |

GPU 분할 결과는 같은 분할의 직렬/파이프라인 사이에서는 일치했지만 원래
비분할 모델과는 수치 차이가 있습니다. 주행 정확도 허용 기준을 설정하거나
실제 주행 경로에서 동등성을 입증하지 않았습니다.

## 수정 및 검증

- 32-step 모델의 시간 이력 간격을 기본값 2에서 4로 수정. 완전 이력 판정은
  66프레임에서 132프레임으로 변경. 과거 stride-2 결과는 시간 이력 정확성
  검증으로 사용할 수 없습니다.
- 전송 기한, 반환 버퍼 소유권, 입력/출력 유효성 검사와 실패 후 중단을 강화.
- 수신 인증 중 불필요한 대용량 복사를 제거하되 wire format과 인증은 유지.
  맥에서 절감한 시간은 약 0.012ms로, 수십 ms 지연을 해결한 것은 아닙니다.
- 준비·송신·수신 대기·검증 및 서버 준비 시간을 분리 기록.
- 사전 적재 NV12 전처리, native gather, 모델 분할·파이프라인 및 순수 통신
  측정 도구를 추가. 실험용 분할 코드는 앱/서버에서 자동 사용하지 않습니다.
- 최신 단위 테스트 78개, Ruff, diff 공백 검사를 통과했습니다.

## 다음 우선순위

차량에서 분리한 3X에서 실제 USB 연결 모드와 모델 없는 왕복 지연을 먼저
측정하고, 카메라 읽기/동기화·준비·전송·맥 추론·응답 구간을 구분해야 합니다.
로컬 modeld 안에 동기식 GPU readback을 다시 넣지 않습니다. Chestnut의
묶음 전송·이중 버퍼·완료 확인 원칙을 적용하되, 전용 USB/PCIe 경로가 Mac의
TCP/NCM 경로와 같다고 가정하지 않습니다. IPv4/DHCP는 아직 활성화하지 않았습니다.

실제 GPU/ANE 하드웨어 카운터는 관리자 인증 제한으로 수집하지 못했습니다.
기존 로컬 모델과 최신 공식 Chestnut 모델의 동일 체크포인트 여부, 변환물의
해시 연결, 장시간 수치 동등성 및 실기기 안정성도 미검증입니다.
